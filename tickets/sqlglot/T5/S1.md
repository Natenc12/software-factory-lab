# SQLite `UPDATE OR REPLACE` (and the other conflict actions) fails to parse

## Problem

SQLite lets an `UPDATE` say what to do when it hits a constraint conflict: `UPDATE OR REPLACE`,
`OR IGNORE`, `OR ABORT`, `OR FAIL` and `OR ROLLBACK`. sqlglot already reads the same prefix on
`INSERT` (`INSERT OR REPLACE` is covered in `tests/dialects/test_sqlite.py`), but not on `UPDATE`:

```python
import sqlglot

sqlglot.parse_one("UPDATE OR REPLACE t SET b = 'x'", read="sqlite")
# sqlglot.errors.ParseError: Expected table name but got <Token token_type: TokenType.OR, text: OR, ...>
```

The other four actions fail the same way. SQLite 3.45 accepts all five
(https://www.sqlite.org/lang_update.html, https://www.sqlite.org/lang_conflict.html).

## Why it matters

Valid SQLite that people run every day cannot be parsed, formatted or translated at all.

## Scope

**In**
- Reading and writing `UPDATE OR <action>` for SQLite, and for sqlglot's default dialect.
- What happens when such a statement is written for a dialect that has no equivalent.
- Tests.

**Out**
- `INSERT OR ...` and `ON CONFLICT` clauses, which already work and must not change.
- Adding `UPDATE OR` to dialects other than SQLite and the default one.

## Decisions

- SQLite and the default dialect read and write all five actions, upper or lower case, written back
  in upper case: `update or ignore t set b = 'x'` becomes `UPDATE OR IGNORE t SET b = 'x'`.
- `UPDATE OR` followed by anything other than one of the five actions is a parse error.
- Writing an `UPDATE OR <action>` for a dialect that has nothing like it (for example Postgres, MySQL
  and Teradata) reports it as unsupported, the same way sqlglot reports other things it cannot
  translate, so `unsupported_level=ErrorLevel.RAISE` raises `UnsupportedError`. A plain `UPDATE` is
  written exactly as today.

## Done when

- [ ] In SQLite, `UPDATE OR <action> t SET b = 'x' WHERE id = 1` reads as an UPDATE and writes back
      unchanged for each of `ABORT`, `FAIL`, `IGNORE`, `REPLACE` and `ROLLBACK`, and so does
      `UPDATE OR REPLACE t AS u SET b = 'x' FROM s WHERE u.id = s.id RETURNING *`.
- [ ] `update or ignore t set b = 'x'` (SQLite) writes back as `UPDATE OR IGNORE t SET b = 'x'`.
- [ ] `UPDATE OR IGNORE t SET b = 'x'` reads and writes back unchanged in the default dialect, and
      reading it as SQLite and writing it for the default dialect leaves it unchanged too.
- [ ] Reading `UPDATE OR IGNORE t SET b = 'x'` as SQLite and writing it for Postgres, MySQL or
      Teradata with `unsupported_level=ErrorLevel.RAISE` raises `UnsupportedError`.
- [ ] `UPDATE OR t SET b = 'x'` (SQLite) raises `ParseError`.
- [ ] `INSERT OR REPLACE INTO t VALUES (1)` (SQLite) still writes back unchanged, and
      `UPDATE t SET b = 'x'` read as SQLite is still written for Postgres as `UPDATE t SET b = 'x'`.
- [ ] Tests that fail on today's code and pass with the fix are added.
- [ ] Every existing test passes.
