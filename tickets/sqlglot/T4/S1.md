# Spark's `EXISTS(array, lambda)` loses its condition when written to other dialects

## Problem

Spark, Databricks and Hive have a higher-order array function `EXISTS(arr, x -> <condition>)`: true
when any element of the array meets the condition. sqlglot reads it fine, but when it writes the
query for any other dialect it drops the condition and keeps only the array:

```python
import sqlglot

for dst in ("duckdb", "trino", "postgres", "bigquery", "mysql"):
    print(dst, sqlglot.transpile("SELECT EXISTS(arr, x -> x > 2) FROM t", read="spark", write=dst)[0])
# duckdb   SELECT EXISTS(arr) FROM t
# trino    SELECT EXISTS(arr) FROM t
# postgres SELECT EXISTS(arr) FROM t
# bigquery SELECT EXISTS(arr) FROM t
# mysql    SELECT EXISTS(arr) FROM t
```

No warning is given, even with `unsupported_level=ErrorLevel.RAISE`. In DuckDB the output does not
even parse (`Parser Error: syntax error at or near "arr"`).

## Why it matters

The condition is the whole point of the call. Dropping it silently produces SQL that either fails or
means something else, and the caller has no signal that anything went wrong.

## Scope

**In**
- How `EXISTS(array, lambda)` read from Spark, Databricks or Hive is written for other dialects.
- Tests.

**Out**
- `EXISTS (subquery)`, which must stay exactly as it is in every dialect.
- Spark's `FORALL(arr, lambda)`, which has its own problems; leave it for another change.
- Snowflake: what it should produce here is still being looked into.

## Decisions

- Spark, Databricks and Hive keep writing `EXISTS(arr, x -> ...)` as they do today.
- Presto and Trino have `ANY_MATCH`, which means the same thing, so they write
  `ANY_MATCH(arr, x -> ...)`.
- DuckDB, Postgres and BigQuery can filter an array, so they get an equivalent expression that gives
  the same answer. How it is spelled is up to you.
- A dialect that has no way to express it, such as MySQL, reports it as unsupported (the same way
  sqlglot reports other things it cannot translate), so `unsupported_level=ErrorLevel.RAISE` raises
  `UnsupportedError`.

## Done when

- [ ] Writing `SELECT EXISTS(arr, x -> x > 2) FROM t` (read as Spark) gives the same text for Spark,
      Databricks and Hive, and `SELECT ANY_MATCH(arr, x -> x > 2) FROM t` for Presto and Trino.
- [ ] The DuckDB output, run on DuckDB over arrays `[1, 2, 3]`, `[1]`, `[]` and `NULL`, gives `true`,
      `false`, `false` and `NULL`, whether the query was read as Spark or as Databricks.
- [ ] The Postgres and BigQuery outputs still contain the condition (`x > 2`), and none of these
      outputs raise with `unsupported_level=ErrorLevel.RAISE`.
- [ ] Writing it for MySQL with `unsupported_level=ErrorLevel.RAISE` raises `UnsupportedError`.
- [ ] `SELECT * FROM t WHERE EXISTS(SELECT 1 FROM u WHERE u.id = t.id)` is written unchanged for
      DuckDB, Postgres, BigQuery, Presto, MySQL and Spark.
- [ ] Tests that fail on today's code and pass with the fix are added.
- [ ] Every existing test passes.
