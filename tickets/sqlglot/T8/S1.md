# Make `python-dateutil` a required dependency so date folding is always on

## Problem

The optimizer folds constant date arithmetic only when `python-dateutil` happens to be installed.
With it, `DATE '2021-01-31' + INTERVAL '1' MONTH` simplifies to `CAST('2021-02-28' AS DATE)`; without
it, the expression is left as it is. You can see both on the current code:

```python
import sys
from unittest import mock
from sqlglot import parse_one
from sqlglot.optimizer.simplify import simplify

sql = "DATE '2021-01-31' + INTERVAL '1' MONTH"
print(simplify(parse_one(sql)).sql())
# CAST('2021-02-28' AS DATE)

with mock.patch.dict(sys.modules, {"dateutil": None, "dateutil.relativedelta": None}):
    print(simplify(parse_one(sql)).sql())
# CAST('2021-01-31' AS DATE) + INTERVAL '1' MONTH
```

Our laptops have `dateutil` (the dev extras pull it in), but the slim image our pipeline runs in does
not. So the optimizer gives different SQL in CI than on a laptop, and our golden-file tests for
generated SQL fail depending on where they run. The same happens for `DATE_TRUNC` comparisons, which
are rewritten into date ranges only when `dateutil` is present.

## Why it matters

The same input should give the same output everywhere. Right now whether a query gets simplified
depends on what else happens to be installed, which nobody expects and which is hard to debug.

## Scope

**In**
- Packaging: add `python-dateutil` to sqlglot's install requirements.
- `sqlglot/optimizer/simplify.py`: import `dateutil` normally and drop the code paths that handle
  it being missing.
- The README section that describes `dateutil` as optional.
- Tests.

**Out**
- Any change to what the folded results are when `dateutil` is installed.
- Other optimizer rules.

## Decisions

- `python-dateutil` becomes a required dependency of sqlglot, installed with it.
- Folding results stay exactly as they are today with `dateutil` installed.

## Done when

- [ ] `pip install sqlglot` brings in `python-dateutil`.
- [ ] Folding gives the same results in every environment, for example
      `DATE '2021-01-31' + INTERVAL '1' MONTH` simplifies to `CAST('2021-02-28' AS DATE)` and
      `DATE_TRUNC('month', x) = DATE '2021-01-01'` simplifies to
      `x < CAST('2021-02-01' AS DATE) AND x >= CAST('2021-01-01' AS DATE)`.
- [ ] Every existing test passes.

## Notes for the implementer

- Set up with `uv venv -p 3.13 .venv && uv pip install -p .venv -e ".[dev]"`, then run the tests with
  `PATH=$PWD/.venv/bin:$PATH SKIP_INTEGRATION=1 python -m unittest` (one test calls `python` by name,
  so the virtual environment has to be first on `PATH`).
