# Snowflake stage paths and `file://` paths get cut off at `--`, `//` or `/*`

## Problem

With `read="snowflake"`, an unquoted stage path or `file://` path that contains `--`, `//` or `/*` is
read as if a comment started there. The path is cut short, or the statement fails to parse.
Reproduced on the current code:

```python
from sqlglot import parse_one

parse_one("select $1 from @s/a--b", read="snowflake").sql("snowflake")
# 'SELECT $1 FROM @s/a /* b */'        expected 'SELECT $1 FROM @s/a--b'

parse_one("select $1 from @s/a//b", read="snowflake").sql("snowflake")
# 'SELECT $1 FROM @s/a /* b */'        expected 'SELECT $1 FROM @s/a//b'

parse_one("select $1 from @s/a/*b", read="snowflake")
# TokenError                          expected 'SELECT $1 FROM @s/a/*b'

parse_one("copy into t from @s/a--b/c", read="snowflake").sql("snowflake")
# 'COPY INTO t FROM @s/a /* b/c */'    expected 'COPY INTO t FROM @s/a--b/c'

parse_one("put file:///tmp/a--b @s/p", read="snowflake").sql("snowflake")
# "PUT 'file:///tmp/a' put file:///tmp/a /* b @s/p */"   expected "PUT 'file:///tmp/a--b' @s/p"
```

`LIST @s/a--b` has the same problem. Quoted paths such as `'@s/a--b'` are already handled correctly.

## Why it matters

It is easy to miss: `@s/a--b` and `@s/a--c` come out as the same statement, so the SQL we write back
silently reads from, or writes to, a different location than the one the user gave.

## Scope

**In**
- How Snowflake reads unquoted stage paths (`@stage/path`, `@~/path`, `@%table/path`,
  `@db.schema.stage/path`, `@"quoted stage"/path`) and unquoted `file://` paths, wherever they appear
  (`SELECT ... FROM`, `COPY INTO`, `LIST`, `PUT`, and so on).
- Tests.

**Out**
- Other dialects.
- Quoted paths such as `'@s/a--b'`, which already work.

## Decisions

These are how Snowflake itself behaves (checked against a live account by unloading files to unquoted
paths and listing them):

- An unquoted path ends at whitespace or at one of `` , ; ( ) ' ` ~ < > | ``. The exception is `~`
  right after `@`, since `@~` is the user stage.
- Everything else, including `--`, `//`, `/*`, `*/`, `#`, `=` and `"`, is part of the path.
- A comment after whitespace is still a comment: `select $1 from @stg/a -- note` reads the path `@stg/a`
  and keeps the comment.
- The same rules apply to `file://` paths in `PUT`.
