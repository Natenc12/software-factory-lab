# Have the optimizer tidy up `COALESCE` calls

## Problem

A lot of the SQL we feed through `optimize()` comes from templates that pad `COALESCE` with `NULL`
arguments, so we end up with things like `COALESCE(NULL, a, NULL, b)`. The optimizer leaves them
exactly as they are:

```python
from sqlglot import parse_one
from sqlglot.optimizer.simplify import simplify

simplify(parse_one("COALESCE(NULL, x)")).sql()           # 'COALESCE(NULL, x)'
simplify(parse_one("COALESCE(x, NULL, y)")).sql()        # 'COALESCE(x, NULL, y)'
simplify(parse_one("COALESCE(NULL, NULL)")).sql()        # 'COALESCE(NULL, NULL)'
```

`simplify()` has a `coalesce_simplification` option, but it is off by default and does something
else (it rewrites comparisons against a `COALESCE`); even with it on, the `NULL` arguments stay.

## Why it matters

The optimized SQL is what people read and diff in reviews, and these leftovers make it noisier than
it needs to be for no benefit: a literal `NULL` argument can never be the result of a `COALESCE`.

## Scope

**In**
- Simplifying the arguments of `COALESCE` in `sqlglot/optimizer/simplify.py`, and so in `optimize()`.
- Existing expectations in `tests/fixtures/optimizer/simplify.sql` that show the old output.
- Tests.

**Out**
- Transpiling without the optimizer: `transpile()` must keep writing `COALESCE` exactly as given.
- The comparison rewrite that `coalesce_simplification=True` turns on.
- Other functions.

## Decisions

- Literal `NULL` arguments are removed wherever they appear. If one argument is left, the
  `COALESCE` is replaced by it; if none is left, the result is `NULL`.
- This happens in the default `simplify()` (and therefore in `optimize()`), whether or not
  `coalesce_simplification` is on.
- `COALESCE` used as a Spark partitioning hint (`/*+ COALESCE(3) */`) is left alone.
- **Not yet decided:** what to do with the arguments that come after one that can never be `NULL`
  (a non-`NULL` literal such as `0` or `'a'`), as in `COALESCE(x, 0, y)`.

## Done when

- [ ] `COALESCE(NULL, x)` and `COALESCE(x, NULL)` simplify to `x`; `COALESCE(x, NULL, y)` and
      `COALESCE(NULL, NULL, x, NULL, y)` to `COALESCE(x, y)`; `COALESCE(NULL, NULL)` to `NULL`;
      `COALESCE(x, y)` stays as it is. The same results with `coalesce_simplification=True`.
- [ ] `optimize("SELECT COALESCE(NULL, a, NULL, b) AS c FROM t", schema={"t": {"a": "INT", "b": "INT"}})`
      gives `SELECT COALESCE("t"."a", "t"."b") AS "c" FROM "t" AS "t"`.
- [ ] `SELECT /*+ COALESCE(3) */ * FROM t` (Spark) is unchanged by `simplify()`.
- [ ] Tests for the above; every existing test passes.
