# Cosine similarity is translated as cosine distance

## Problem

sqlglot has a cosine *distance* function but no cosine *similarity*, and Snowflake's
`VECTOR_COSINE_SIMILARITY` is read as a distance. The two are not the same thing: similarity is
`1 - distance`. So translating to or from Snowflake silently flips the meaning:

```python
import sqlglot

sqlglot.transpile("SELECT VECTOR_COSINE_SIMILARITY(a, b) FROM t", read="snowflake", write="duckdb")
# ['SELECT LIST_COSINE_DISTANCE(a, b) FROM t']      a distance, where the query asked for a similarity

sqlglot.transpile("SELECT VECTOR_COSINE_SIMILARITY(a, b) FROM t", read="snowflake", write="bigquery")
# ['SELECT COSINE_DISTANCE(a, b) FROM t']

sqlglot.transpile("SELECT COSINE_DISTANCE(a, b) FROM t", read="bigquery", write="snowflake")
# ['SELECT VECTOR_COSINE_SIMILARITY(a, b) FROM t']   the other way round

sqlglot.transpile("SELECT LIST_COSINE_SIMILARITY(a, b) FROM t", read="duckdb", write="snowflake")
# ['SELECT LIST_COSINE_SIMILARITY(a, b) FROM t']      not a Snowflake function
```

## Why it matters

We move vector-search queries between Snowflake, DuckDB and BigQuery. A similarity that turns into a
distance ranks results in exactly the reverse order, with no error and no warning.

## Scope

**In**
- Cosine similarity as a function of its own, next to the existing cosine distance.
- Reading it from Snowflake (`VECTOR_COSINE_SIMILARITY`) and DuckDB (`LIST_COSINE_SIMILARITY`), and
  writing it for Snowflake, DuckDB, BigQuery and ClickHouse.
- Writing cosine distance for Snowflake, which has no distance function of its own.
- Type inference for Snowflake (`VECTOR_COSINE_SIMILARITY` returns a `DOUBLE`, as today).
- Tests.

**Out**
- DuckDB's `ARRAY_COSINE_SIMILARITY` and `ARRAY_COSINE_DISTANCE` (the fixed-size array versions),
  which must keep reading and writing exactly as they do today.
- Other vector functions (L1/L2 distance, inner product).
- Postgres / pgvector operators.

## Decisions

- Snowflake writes similarity as `VECTOR_COSINE_SIMILARITY(a, b)`, and distance as
  `(1 - VECTOR_COSINE_SIMILARITY(a, b))`.
- DuckDB writes similarity as `LIST_COSINE_SIMILARITY(a, b)`; distance stays `LIST_COSINE_DISTANCE(a, b)`.
- BigQuery and ClickHouse have only a distance, so similarity is written as
  `(1 - COSINE_DISTANCE(a, b))` and `(1 - cosineDistance(a, b))`. The parentheses are always there,
  so the result is right inside a larger expression too.
- Cosine distance is written for BigQuery, ClickHouse and DuckDB exactly as today.
- The default dialect spells it `COSINE_SIMILARITY(a, b)`.

## Done when

- [ ] `SELECT VECTOR_COSINE_SIMILARITY(a, b) FROM t` read as Snowflake is written back unchanged for
      Snowflake, as `SELECT LIST_COSINE_SIMILARITY(a, b) FROM t` for DuckDB,
      `SELECT (1 - COSINE_DISTANCE(a, b)) FROM t` for BigQuery and
      `SELECT (1 - cosineDistance(a, b)) FROM t` for ClickHouse.
- [ ] `SELECT VECTOR_COSINE_SIMILARITY(a, b) * 2 FROM t` (Snowflake) is written for BigQuery as
      `SELECT (1 - COSINE_DISTANCE(a, b)) * 2 FROM t`.
- [ ] The DuckDB translation of `SELECT VECTOR_COSINE_SIMILARITY([1.0, 0.0], [1.0, 1.0])` returns
      about 0.7071 when run on DuckDB.

      (ClickHouse) and `SELECT LIST_COSINE_DISTANCE(a, b) FROM t` (DuckDB) are all written for
      Snowflake as `SELECT (1 - VECTOR_COSINE_SIMILARITY(a, b)) FROM t`, and
      `SELECT COSINE_DISTANCE(a, b) * 2 FROM t` (BigQuery) as
      `SELECT (1 - VECTOR_COSINE_SIMILARITY(a, b)) * 2 FROM t`.
- [ ] `SELECT COSINE_DISTANCE(a, b) FROM t` (BigQuery) is still written for DuckDB as
      `SELECT LIST_COSINE_DISTANCE(a, b) FROM t`.

      `SELECT VECTOR_COSINE_SIMILARITY(a, b) FROM t` for Snowflake and
      `SELECT (1 - COSINE_DISTANCE(a, b)) FROM t` for BigQuery.
- [ ] `SELECT ARRAY_COSINE_SIMILARITY(a, b) FROM t` (DuckDB) and `SELECT COSINE_SIMILARITY(a, b) FROM t`
