# A realm that ends in a backslash breaks the `WWW-Authenticate` header

## Problem

When an auth middleware refuses a request with 401, it puts the configured `realm` inside a quoted
string in the `WWW-Authenticate` header, for example `Basic realm="Secure Area"`. Double quotes in the
realm are escaped today, but backslashes are not. In a quoted string a backslash escapes the next
character, so a realm with a backslash in it reaches clients as a different value, and a realm ending
in a backslash escapes the closing quote and leaves the header malformed:

```ts
app.use('/auth/*', basicAuth({ username: 'user', password: 'pass', realm: 'my "api"\\' }))
// 401 WWW-Authenticate today:  Basic realm="my \"api\"\"
```

Here the last `\"` reads as an escaped quote, so the quoted string never ends. Clients that parse
the header strictly either reject it or read a realm that is not the one configured.

The same happens with every middleware that writes a realm into that header: `basicAuth`,
`bearerAuth`, `jwt` and `jwk` (in `jwt` and `jwk` the realm defaults to the request URL when none is
set).

## Why it matters

A server must send a well-formed header whatever text an app puts in its realm. A malformed
`WWW-Authenticate` header can break the login prompt or the client's error handling.

## Scope

**In**
- Escaping the realm correctly in the `WWW-Authenticate` header of all four middlewares, and the
  `error_description` value that `jwt` and `jwk` put in the same header.
- Tests.

**Out**
- The status codes, the `error` values, and the wording of each `error_description`.
- What each middleware accepts as a valid credential.
- The separate packages under `adapters/`.

## Decisions

- Inside the quoted string, a backslash is sent as `\\` and a double quote as `\"`; every other
  character is sent as it is. A realm without backslashes or quotes comes out exactly as today.

## Done when

- [ ] With `realm: 'my "api"\\'`, `basicAuth` sends `Basic realm="my \"api\"\\"` and `bearerAuth`
      sends `Bearer realm="my \"api\"\\"`.
- [ ] With `realm: 'my\\api\\'` and no credentials, `jwt` and `jwk` send
      `Bearer realm="my\\api\\",error="invalid_request",error_description="no authorization included in request"`.
- [ ] Tests that fail on today's code and pass with the fix are added.
- [ ] `pnpm test` passes (after `pnpm run build`), and `pnpm run lint` and `pnpm run format` are clean.

## Notes for the implementer

- The middlewares are in `src/middleware/` (`basic-auth`, `bearer-auth`, `jwt`, `jwk`), each with its
  tests beside it. The header values in this ticket are shown as they appear on the wire, not as
  JavaScript string literals.
- Install with `pnpm install`, build with `pnpm run build` (the tests in `build/` need it), then run
  `pnpm test`. A single folder runs with `pnpm exec vp test --run src/middleware`.
