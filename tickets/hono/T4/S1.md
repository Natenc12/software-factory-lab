# An async component that returns `null`, a boolean or a number fails to render

## Problem

A function component may return nothing: a sync component that returns `null`, `undefined` or `false`
renders as nothing, `true` also renders as nothing, and a number renders as its digits. The same
component written as `async` breaks rendering instead:

```tsx
import { Hono } from 'hono'

const app = new Hono()
const Maybe = async ({ show }: { show: boolean }) => (show ? <p>hi</p> : null)

app.get('/', (c) =>
  c.html(
    <div>
      <Maybe show={false} />
    </div>
  )
)
```

`GET /` answers `500 Internal Server Error` instead of `<div></div>`. Today:

- an async component resolving to `null` or `undefined` throws a `TypeError` while the page is turned
  into a string (`Cannot read properties of null` or `of undefined`), and `false`, `true` or a number throws
  `TypeError: str.search is not a function`;
- inside `<Suspense>` with `renderToReadableStream` (from `hono/jsx/streaming`), the stream never
  replaces the fallback: it ends with `<template id="H:0"></template><p>loading</p><!--/$-->` and an
  unhandled promise rejection;
- the `html` tagged template (`hono/html`) has the same problem with a promise that resolves to one of
  these values: `` html`<p>${Promise.resolve(null)}</p>` `` fails instead of giving `<p></p>`.

TypeScript also refuses `async () => null` as a component today, though it accepts `() => null`.

## Why it matters

"Render nothing" is the ordinary way for a component to opt out, and an async component that loads
data and finds none needs it most. Writing the same component as `async` must not turn an empty
result into a server error.

## Scope

**In**
- Rendering to a string (`toString()`, `c.html(...)`), streaming with `Suspense`, and the `html`
  tagged template, for promises that resolve to `null`, `undefined`, a boolean or a number.
- The component type, so an async component may return what a sync one may.
- Tests.

**Out**
- The client-side renderer in `src/jsx/dom/`.
- How strings, elements and arrays render, sync or async.
- Escaping rules.

## Decisions

- A promise resolves to the same output as its value written directly: `null`, `undefined`, `false`
  and `true` render as nothing; a number renders as its digits (`0` as `0`).
- In a `Suspense` boundary, an async child that resolves to nothing replaces the fallback with empty
  content; one that resolves to `1` replaces it with `1`.

## Done when

- [ ] The example answers `200` with `<div></div>`.
- [ ] For each of `null`, `undefined`, `false`, `true`, `0` and `1`, `<div><AsyncValue /></div>` with
      `const AsyncValue = async () => value` renders exactly as the sync version does (`<div></div>`,
      or `<div>0</div>` and `<div>1</div>`).
- [ ] `` html`<p>${Promise.resolve(value)}</p>` `` gives `<p></p>` for `null`, `undefined`, `false`
      and `true`, and `<p>0</p>` and `<p>1</p>` for `0` and `1`.
- [ ] The streaming case replaces the fallback with empty content for `null` and `false`, and with `1`
      for `1`, with no unhandled rejection.
- [ ] Tests that fail on today's code and pass with the fix are added.
- [ ] `pnpm test` passes (after `pnpm run build`), and `pnpm run lint` and `pnpm run format` are clean.

## Notes for the implementer

- The JSX renderer is in `src/jsx/` (`base.ts`, `streaming.ts`), the `html` tag in `src/helper/html/`,
  and the shared string-building helpers in `src/utils/html.ts`. Tests sit beside each file.
- Install with `pnpm install`, build with `pnpm run build` (the tests in `build/` need it), then run
  `pnpm test`. A single folder runs with `pnpm exec vp test --run src/jsx`.
- The Node adapter's "Should call onAbort" tests (`runtime-tests/node`) are timing-sensitive and can
  fail on a busy machine; that is known and not part of this ticket.
