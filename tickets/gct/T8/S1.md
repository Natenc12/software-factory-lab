## What the change is meant to do

The author's description of the change:

> Adds `GET /classes/{class_id}/files`, so the client can show every upload in a class with its
> status, and a library function `list_class_files(conn, *, class_id, owner_id, limit=50, offset=0,
> status=None)` in `src/gct/files.py` behind it.
>
> - Files come newest first; files created at the same moment are ordered by `file_id`, so pages
>   never overlap.
> - Paging: `page` starts at 1 (default 1) and `per_page` is 1 to 100 (default 20). Page 1 is the
>   newest `per_page` files.
> - `?status=queued|processing|ready|failed` keeps only files in that status.
> - Each item carries `file_id`, `filename`, `status`, `failed_reason`, the same `message` sentence
>   `GET /files/{file_id}` gives for that status, and `created_at` as an ISO 8601 string.
> - A class with no files answers `200` with an empty `files` list. A missing class, or another
>   owner's class, answers `404` `class_not_found`, the same for both. A malformed id answers `400`
>   `bad_class_id`.
> - `list_class_files` returns `None` when the owner has no such class.
> - `web/openapi.json` is regenerated for the new route. Tests cover the library function.
