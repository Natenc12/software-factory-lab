# 422 replies break on odd bodies / echo huge bodies back

Two things seen with the API's validation errors:

- POST /classes with a single 0xff byte as the body (no content type) gives a 500 "internal" instead of
  a 422. Looks like the error handler chokes on the raw bytes it's trying to echo.
- POST /classes with a ~2 MB body labelled multipart/form-data gives a 422, but the reply contains the
  whole body again (about 2 MB back). The JSON body size limit doesn't apply to multipart on purpose.

The 422 should never become a 500, and it shouldn't send back a reply the size of the request. Keep the
normal 422 shape. Error handling is in `src/gct/api/errors.py`. Add tests.
