# replace a file with a new version

Students want to upload a new version of a lecture without ending up with two files. Add
`PUT /files/{file_id}` with the new file (multipart `file`). The file should keep working from its old
content until the new version is processed, and if the new version fails the old one should stay.
`GET /files/{file_id}` should show that a replacement is pending or failed. Don't delete staged files
(we keep them). Don't let anyone replace another owner's file, or a file that's still processing.
Also keep a version history: each upload of a file is version 1, 2, 3... (failed ones too), with
`GET /files/{file_id}/versions` listing them and whether each was published or failed. Files that are
already in the database should show up as version 1.
