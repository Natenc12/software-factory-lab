# Library functions pass a caller's id spelling straight to Postgres, or catch too little of a bad one

## Problem

Python's `uuid.UUID` accepts more spellings of an id than Postgres's `::uuid` cast does: it also takes
`urn:uuid:<id>`, and it ignores hyphens wherever they fall. `enqueue` (`src/gct/jobs/queue.py`)
already handles this: it parses the caller's `class_id` once, binds the canonical spelling, and turns
every way the parser can reject a value into a `ValueError` with a useful message. Four other library
entry points do not.

**Two bind the caller's spelling raw into a `::uuid` cast.**
- `retrieve` (`src/gct/retriever/retrieve.py`) binds `class_id` raw in both of its queries. A
  `urn:uuid:` spelling, which names a real class, fails inside Postgres with
  `InvalidTextRepresentation`. Worse, `retrieve` has no transaction of its own, so on a connection
  that is not in autocommit the failed statement leaves the caller's open transaction aborted, and
  every later statement on that connection fails too.
- `index_file` (`src/gct/ingest/index.py`) binds `class_id` raw, for the `files` row and for every
  chunk. It is reached from `ingest_file` (`src/gct/ingest/pipeline.py`), which parses the file and
  pays for embeddings first, so a bad `class_id` costs a full embedding run before it fails.

**Two catch only one of the parser's three errors.** `class_exists` (`src/gct/classes.py`) and
`get_file_status` (`src/gct/files.py`) parse their id themselves but catch only `ValueError`.
`uuid.UUID` raises `TypeError` for `None` and `AttributeError` for a non-string such as an int or an
already-parsed `uuid.UUID`, so those escape with the parser's own message instead of the function's:

```
class_exists(conn, class_id=None, owner_id=o)              -> TypeError
class_exists(conn, class_id=uuid.UUID(cid), owner_id=o)    -> AttributeError
get_file_status(conn, file_id=None, owner_id=o)            -> TypeError
```

Nobody hits this over HTTP today, because every route parses the id before calling the library. The
protection lives in the callers, so the next script, endpoint or eval run that calls these directly
gets the database error or the parser's error.

## Why it matters

A spelling Python calls valid should not turn into a database error, a poisoned connection, or a paid
embedding run that is then thrown away. A bad id should be refused at the function's own door, in its
own words.

## Scope

**In**
- `class_exists`, `get_file_status`, `retrieve`, `index_file`, and `ingest_file`'s handling of
  `class_id`.
- Tests for each.

**Out**
- `enqueue`: it is already right; leave its behaviour as it is.
- `ingest_file`'s existing `file_id` rule (it already refuses a non-canonical `file_id`).
- Ownership rules (which owner may use which class), and the HTTP routes' own 400 messages.
- The schema and every file in `migrations/`.

## Decisions

- **Lenient where a person supplies the id.** `class_id` in `class_exists`, `retrieve`, `index_file`
  (the argument and the `class_id` on each chunk) and `ingest_file`, and `file_id` in
  `get_file_status`: every spelling `uuid.UUID` accepts (plain, upper case, in braces, 32 hex digits
  with no hyphens, `urn:uuid:<id>`) behaves exactly like the canonical spelling and reaches the same
  rows. What is stored is always the canonical spelling.
- **Strict where the id comes from the database.** `file_id` in `index_file` must already be the
  standard hyphenated 36-character form (either letter case), the same rule `ingest_file` applies to
  `file_id` today. Any other spelling is refused, not converted.
- **Ids are strings.** `None`, an int, an already-parsed `uuid.UUID`, or a string that is not a uuid
  is refused with `ValueError`, never `TypeError` or `AttributeError`. The message names the function
  and the parameter (`class_id` or `file_id`) and says what to pass instead.
- Refusals happen before any write and, in `ingest_file`, before any embedding call.
- A refusal in `retrieve` leaves the caller's connection usable: its open transaction is not aborted.

## Done when

- [ ] Each of the five functions accepts every spelling its rule allows and refuses everything else
      with `ValueError` naming the parameter.
- [ ] `retrieve` with a `urn:uuid:` class id returns the same chunks as with the canonical one, and a
      refused call leaves the connection able to run the next statement.
- [ ] `ingest_file` with a bad `class_id` raises before the embedder is called.
- [ ] Tests for both directions (accepted spellings, refused values) at every site.
- [ ] Every existing test passes; `uv run ruff check` and `uv run ruff format --check .` are clean.

## Notes for the implementer

- `enqueue`'s guard and its docstring, and the `file_id` guard in `ingest_file`, are the two existing
  shapes (lenient and strict).
- Tests run with `uv run pytest -m "not live"` against the Postgres in `DATABASE_URL`, after
  `uv run python scripts/migrate.py`. `tests/gct/retriever/conftest.py` has fixtures for seeding
  chunks and a controllable embedder.
