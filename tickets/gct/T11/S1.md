# Retry transient provider errors in the worker instead of failing the file

## Problem

Last night the embedding provider had a rough hour of 429s and timeouts, and this morning dozens of
files are `failed` with reason `transient_exhausted`. Students have to upload them again. The
worker gives up on a file at the first transient provider error: `process_one`
(`src/gct/jobs/worker.py`) catches `TransientEmbeddingError` from `ingest_file` and the file ends up
failed, with no second try.

## Why it matters

A provider hiccup is not the student's fault and should not cost them a re-upload. A short retry
inside the worker would have ridden out most of last night's errors.

## Scope

**In**
- `process_one` in `src/gct/jobs/worker.py`.
- Tests.

**Out**
- The provider adapter (`src/gct/providers/`) and the embedding batch sizes.
- Terminal failures (`unparseable`, `protected`, `unsupported`, `empty`, `too_long`): those are bad
  input and must still fail at once.
- The API, the schema and the migrations.

## Decisions

- When `ingest_file` raises `TransientEmbeddingError`, `process_one` tries it again, up to three
  tries in total, two seconds apart.
- If the third try also fails, the file fails as it does today, with reason `transient_exhausted`.
- A terminal parse failure is never retried.

## Done when

- [ ] A file whose first embedding call gets a 429 and whose next call succeeds ends `ready`, with
      its chunks.
- [ ] A file whose provider keeps failing ends `failed` with `transient_exhausted`.
- [ ] A corrupt file still fails at once as `unparseable`.
- [ ] Tests for the above; every existing test passes; `uv run ruff check` and
      `uv run ruff format --check .` are clean.

## Notes for the implementer

- `tests/gct/jobs/test_worker.py` has a `FakeEmbeddings` that can raise `TransientEmbeddingError` on
  cue, and `tests/conftest.py` has `worker_db` (holds the worker lock, needed for `process_one`).
- Tests run with `uv run pytest -m "not live"` against `DATABASE_URL`, after
  `uv run python scripts/migrate.py`.
