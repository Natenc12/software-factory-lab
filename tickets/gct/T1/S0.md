# files row lies after a retry / re-index

Noticed while looking at the worker: a file can show the failure reason from an earlier attempt even
though it's being retried, or even after the retry worked and it's `ready`. Happens when the worker
fails a file but the job doesn't get settled (crash, lease ran out), so the job gets picked up again.

Also: re-indexing the same file id with a different filename/owner/class updates the chunks but the
`files` row keeps the old filename/owner/class. So the row and its chunks disagree.

Both should be fixed so the `files` row always tells the truth about the current attempt and the
chunks it published. Code is in `src/gct/jobs/worker.py` and `src/gct/ingest/index.py`. Add tests.
