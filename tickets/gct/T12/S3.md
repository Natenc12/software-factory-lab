# Tell "no such file" apart from "someone else's file" in GET /files/{file_id}

## Problem

`GET /files/{file_id}` (`src/gct/api/routers/files.py`) answers `404` with kind `file_not_found` both
for an id that exists nowhere and for a file that belongs to another owner. Support gets tickets
from students saying "my file is gone" and cannot tell whether the student mistyped the id or is
looking at a file under another account (two accounts on one shared laptop, a link pasted from a
classmate).

## Why it matters

Support spends time chasing files that were never lost. A clear answer for the second case would
let the student see at once that they are signed in to the wrong account.

## Scope

**In**
- `GET /files/{file_id}`, and whatever it needs in `src/gct/files.py`.
- Tests.

**Out**
- `POST /files`, `POST /ask` and `POST /classes`.
- The web client under `web/src/`.
- The schema and the migrations.

## Decisions

- When the file exists but belongs to another owner, answer `403` with kind `file_forbidden` and the
  message "This file belongs to another account."
- When the id exists nowhere, keep today's `404` `file_not_found` reply unchanged.
- An owner reading their own file gets exactly today's reply.

## Done when

- [ ] Another owner's file answers `403` `file_forbidden`.
- [ ] An unknown id still answers today's `404`.
- [ ] Tests for the above; every existing test passes; `uv run ruff check` and
      `uv run ruff format --check .` are clean.

## Worked examples

Owner O asks; `M` is O's own file, `T` is a file of another owner P, `X` exists nowhere.

| # | Request (as O) | Reply |
|---|---|---|
| 1 | `GET /files/M` | `200`, exactly today's body |
| 2 | `GET /files/T` | `403 {"error": {"kind": "file_forbidden", "message": "This file belongs to another account.", "detail": null}}` |
| 3 | `GET /files/X` | `404`, exactly today's `file_not_found` body |
| 4 | `GET /files/not-a-uuid` | `400` `bad_file_id`, as today |

## Failure cases that must hold

- The `403` never names the other owner or says anything about the file beyond that it is not O's.
- Any spelling of `T`'s id that `uuid.UUID` accepts gets the same `403`.

## Must not change

- Every other route.
- The `200`, `400` and `404` replies of `GET /files/{file_id}`.
- The schema and the migrations.
- Existing tests: do not delete them or weaken their assertions.

## Acceptance tests

`tests/acceptance/test_file_status_owners.py` is already in the branch. It encodes worked examples 1
and 3 and must pass. It does not cover everything above: the rest of this ticket still applies.

## Notes for the implementer

- `get_file_status` in `src/gct/files.py` returns `None` for both cases today.
- `tests/gct/api/conftest.py` has the `api` fixture. Tests run with `uv run pytest -m "not live"`
  against `DATABASE_URL`, after `uv run python scripts/migrate.py`.
