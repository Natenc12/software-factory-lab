#6 Record when each student was last seen: plan

Contract checked against origin/main: no amendment needed. Ends in a pull request.

What I checked (Builder says)

  • students has exactly id, class_id, name, created_at today; Student has those four fields in that order.
  • Only 0001_init.sql and 0002_answers.sql exist; migrate.py records names and skips applied files, so a new 0003_…sql reaches existing databases.
  • Every Example of done can be played out: migrate(migrations_dir=…) builds a 0001+0002-only database; hide_question hides; ask_question takes asked_at.
  • No existing test builds a Student by hand or compares students after a question is asked, so a new last field without a default breaks none of them.
  • The only place that inserts questions is ask_question.

Defaults I will use

  • New file migrations/0003_student_last_seen.sql: alter table students add column last_seen text, then backfill with max(asked_at) over all of the student's questions, hidden included.
  • ask_question runs one update … set last_seen = ? where id = ? and (last_seen is null or last_seen < ?) in the same transaction as the insert.
  • "Later" means later as text, the same rule SQLite's max() uses for the backfill, so the two always agree. This is right for timestamps in one format (the app's own now() output, or the examples' form).
  • No index or other schema change (Scope Out).
