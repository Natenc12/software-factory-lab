Merge brief: issue #5, students' "last seen" time

PR #19, branch a-t3/last-seen, one commit 515a5cb, up to date with main.

Refresher

The problem. Teachers can't spot a student who has gone quiet. The students table had no record of when a student last asked anything, so finding out meant scanning every question.

The solution. A new migration adds students.last_seen and fills it in for existing students from their latest question (hidden questions count). From now on, ask_question keeps it up to date, but only ever moves it forward. Student carries the value. Nothing displays it yet; that was out of scope.

Blocking: none. Scope departures: none. Reviewer

Non-blocking notes:

  • "Latest" compares timestamps as text, both in the backfill and in the update. This matches the ticket's "largest asked_at", and now() always writes UTC. But an asked_at passed in with a non-UTC offset (such as +05:00) would be ordered wrongly. Nothing in the app passes one today.
  • The question insert and the last_seen update share one transaction with no explicit rollback if the update fails. This is the same pattern the code already used, and the reviewer could not trigger it.
  • Student gains a required field, so any hand-built Student(...) with 4 arguments would break. There are none in the code.
