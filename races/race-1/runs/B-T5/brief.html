Calls made without you

  1. Should have asked The cached answer is also tied to the provider. Your amendment names the class and the text. I kept that key, but each entry also remembers which provider made it (provider.name). A different provider misses the cache and is called. Without this, answer(conn, q, Echo()) after a fake-provider answer would return the fake provider's text stored under "echo". That breaks "same body as without the cache", and only callers who pass a provider are affected. It works exactly like the material check. Say "drop it" if you'd rather not have it.
  2. Low stakes The entry stores a SHA-256 fingerprint of the material, not the material itself, so long course text isn't copied into every entry.
  3. Low stakes tests/conftest.py gets an autouse fixture that empties the cache before and after every test, so tests can't affect each other through the process-wide dict. No existing test function changed.
  4. Low stakes The hidden and missing checks run before the cache lookup, so refusals are exactly as before, and a hidden question never fills the cache.
  5. Low stakes The cache is filled before the answers row is written. If that write failed, the entry would stay, but its body is the provider's real answer for those inputs.
