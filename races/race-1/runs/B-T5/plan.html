#10 Cache answers by question text: the contract contradicts itself

This ticket ends in a pull request. I checked the contract against origin/main. One Decision clashes with two Must not change lines. Building it as written would give students the wrong class's answer.

The problem

Decision: "The cache key is the question text exactly as stored."
Must not change: "For any question, answer() returns the same answer body it would return without the cache" and "Every existing test passes unchanged."

The answer doesn't depend on the text alone. answer() passes the provider the text and the class's material (src/lab/ask.py: provider.answer(question.text, material)), plus whichever provider was passed in. The module's own docstring says it: "the same words asked in two classes can get two different answers." A cache keyed by text alone ignores the material and the provider.

I played the contract as written against a copy of main Builder says (script: runs/B-T5/scratch/repro_textonly.py):

1) same text, two classes ("Where does energy come from?")
   Biology: From the class material: Mitochondria produce energy for the cell.
   Cooking: From the class material: Mitochondria produce energy for the cell.
            without the cache: ... Energy for a long day comes from oats.
2) teacher changes the material with set_material, question answered again
   answer(): From the class material: DNA carries genetic information.
            without the cache: ... Genes carry genetic information too.

These two cases are existing tests, and both would fail: test_same_question_in_two_classes_gets_each_class_answer and test_answering_again_replaces_the_answer in tests/test_ask.py. A provider passed in (like the Echo one in test_answer_uses_given_provider) would also get back another provider's cached answer, stored under its own name.

Decision: what is the cache keyed by?

A. Recommended: key = provider name + the class's material + the question text exactly as stored.
A hit happens only when the provider would get exactly the same inputs, so the answer is always the one it would give anyway. Still no normalising, no table, nothing outside ask.py.
Before (contract as written): Cora in Cooking asks "Where does energy come from?" after Ada asked it in Biology and gets "Mitochondria produce energy…".
After: Cora's question misses the cache and gets "Energy for a long day comes from oats." Ben in Biology asking Ada's "What is DNA?" still hits, with no provider call (your first Example of done is unchanged). After set_material the material differs, so the next answer is fresh with no extra code.
Then: I record the amended Decision and Scope In line in contract.md, build it, and every Example of done and Must not change line stays as you signed it.
B. Key = class id + question text, and clear the cache when material changes.
Before/after for Cora: same fix as A. But stale answers after set_material are only avoided if src/lab/classes.py clears the cache, which is outside Scope In. And a provider passed in still gets another provider's answer unless the key also includes the provider.
Then: the amendment also adds classes.py to Scope In. More moving parts for the same result as A.
C. Keep the text-only key, and loosen Must not change.
After: Cora gets Biology's "Mitochondria…" answer. Fixing that would mean dropping "same answer body as without the cache" and rewriting the two existing tests.
Then: I'd need you to rewrite those Must not change lines. Not recommended: the cache would give wrong answers.
